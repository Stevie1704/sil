# SiL 0.4.0

SiL now supports Linux arm64 with glibc 2.36 or newer. The installer selects
the native archive for the host, and the versioned runtime image includes
`linux/amd64` and `linux/arm64`. Docker on Apple silicon can run the Linux
arm64 image without emulation. [Linux arm64 support](https://github.com/Stevie1704/sil/pull/414)

For deterministic Runs, pin the image digest for your machine class. The
same compiled artifacts, Manifest bytes and dependency versions produce
bit-identical Recordings within one machine class. Compare Recordings from
different machine classes with a tolerance. [Determinism and machine classes](https://github.com/Stevie1704/sil/blob/v0.4.0/SUPPORT.md#determinism-the-exact-boundary)

On Linux arm64, FMI 3.0 requires the FMU to carry its `binaries/aarch64-linux/`
library. FMI 2.0, CPU profiling with perf, and source-scope captures are
x86-64 features. Heap profiling with Heaptrack is supported on both machine
classes. [FMI binary directories](https://github.com/Stevie1704/sil/blob/v0.4.0/docs/fmi.md#binary-directories-per-machine-class) · [Profiling support](https://github.com/Stevie1704/sil/blob/v0.4.0/SUPPORT.md#optional-profiling-backends)

## Upgrade for shared-memory Process participants

The kernel rounds `shm_capacity` up to a multiple of eight to align every
Arena slot header. A protocol-2 client that computes the slot stride from the
Schema's `byte_size` will find slot 1 and later at the wrong offset when the
Schema size is not a multiple of eight. Compute the stride as
`16 + shm_capacity` using the value from the `init` message. That works with
both 0.3.2 and 0.4.0. Keep the Message length equal to the Schema's
`byte_size`. Protocol-1 clients mapping slot zero and Python clients using
`sil.participant` already work with the aligned layout.
[Step protocol](https://github.com/Stevie1704/sil/blob/v0.4.0/docs/step-protocol.md#shared-memory-payloads) · [Arena alignment fix](https://github.com/Stevie1704/sil/pull/417)

## Other changes

- The documentation is available on the [SiL documentation site](https://stevie1704.github.io/sil/),
  with a walkthrough of how SiL schedules a Run and routes Messages.
- Generated scheduler tests compare the ordered Native Activations and
  Process Steps of real Runs with an independent oracle. [Scheduler tests](https://github.com/Stevie1704/sil/pull/406)
- Build and test jobs now default to the CPU count, and the host scheduling
  proof test can extract its pinned archive on Python 3.11.2. [Build and test fixes](https://github.com/Stevie1704/sil/pull/418)

## Compatibility

| Surface | Status in 0.4.0 |
| --- | --- |
| Native participant C ABI and Clock region | Same layouts, including `SIL_ABI_VERSION 1`. Build Native participants for the target machine class and use the runner and shim from the same release. |
| Manifest document | Same version and keys. |
| Step protocol | Versions 1 and 2 with the Arena layout change above. |
| Recording and side-cars | Same Recording format, provenance schema version 2 and failure schema version 1. |
| Runner command line and exit codes | Same runner options and exit code meanings. ARM64 platform refusals are described below. |
| Native schema-generation tool | Same `silschema` interface and generated-header contract. `sil schema import` reads the compiled type, so plain `char` can produce `i8` on x86-64 and `u8` on arm64. |
| Python API and CLI | Same public signatures and commands. FMI and profile availability depend on the host as described above. |
| Container entry point | `sil-run` at `/workspace`, with both image platforms available through the version tag. |

## Run impact

- **Manifest bytes and hashes** have no format or algorithm changes. The
  hash is still SHA-256 of the exact Manifest file bytes.
- **Run behavior** changes for clients that derive their own Arena stride.
  On Linux arm64, use Participants built for arm64 and an arm64 FMU binary
  for FMI 3.0.
- **Exit-code classification** stays the same for the runner. On Linux arm64,
  the FMI 2.0 Importer reports a Manifest error, `sil fmi inspect` returns
  exit `1` for an unusable FMI 2.0 FMU, and the CPU collector refuses at
  preflight with exit `1`.
- **Recording bytes** have no layout change. Matching Recordings across
  releases or machine classes are outside the determinism guarantee.
