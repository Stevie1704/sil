# SiL 0.3.2

This release adds a per-Channel record mode. A Channel can now store each
payload in full, only the SHA-256 of each payload, or nothing. Large sensor
Channels can keep their determinism evidence without the payload write and
I/O. The default stays `full`, and a Manifest without the new key writes the
same bytes as before. The changes since [0.3.1](v0.3.1.md) are in
[PR #399](https://github.com/Stevie1704/sil/pull/399). The README also has new
install instructions and the OpenSSL build requirement.

## Supported machine class and determinism

Unchanged from 0.3.1. Linux x86-64 with glibc 2.36 (Debian bookworm) or
newer. The native archive and the runtime image come from the same pinned
bookworm toolchain. The same compiled artifacts, Manifest bytes and
dependency versions on the same machine class produce identical Recordings.
Bit identity with earlier releases or across machine classes is not promised.

A Channel with record mode `digest` is in the determinism check through its
SHA-256: one different payload byte is a violation, but the check cannot show
how the payloads differ. A Channel with record mode `off` is not in the
comparison. `sil check` names both kinds of Channel in its report. See
[record modes and the determinism check](../running.md#record-modes-and-the-determinism-check).

## Record modes

Each Channel accepts an optional `record` key with one of these values:

| Mode | MCAP Channel metadata | MCAP Schema | Messages |
| --- | --- | --- | --- |
| `full` (default) | none | the Manifest Schema | each payload |
| `digest` | `sil_record: digest`, `sil_schema: <Manifest Schema>` | `sil.Sha256Digest`: one `u8[32]` field `sha256` | one 32-byte SHA-256 of the payload |
| `off` | `sil_record: off` | the Manifest Schema | none; the Channel stays declared |

The digest covers the payload bytes after any Interceptor. The MCAP record
keeps the Virtual time and sequence of each Message, so the Recording bytes
still cover time and order. A reader identifies the mode from `sil_record`
only, never from the Schema name.

```python
m.add_channel("camera.frames", schema="sensor.Frame", transport="shm", record="digest")
m.add_channel("debug.overlay", schema="sensor.Frame", record="off")
```

`sil recording channels`, `show`, `query`, `compare`, `export` and `playback`
decode a digest Channel as one field, `sha256`. These tools refuse a Channel
that has no payload and name its mode:

- A Replay participant whose source Channel is `digest` or `off`: Manifest
  error, exit `2`.
- `sil manifest validate`: a Problem.
- `sil recording window`: exit `2`.

See [record modes](../running.md#record-modes) and the agent steps in
[choose what the Recording stores](../agent-guide.md#choose-what-the-recording-stores).

## Compatibility changes and migration

| Change | Who must act |
| --- | --- |
| A Channel accepts the optional `record` key (`full`, `digest`, `off`). Other values are a Manifest error (exit `2`). | Nobody. A Manifest without the key is unchanged. A Manifest with the key does not load in 0.3.1 or earlier (unknown key, exit `2`). |
| `sil_recording_channels` rows gain `record` and `source_schema`; the text output gains a `RECORD` column. `sil_check_report` gains `record_modes`, which is `null` when the Recording cannot be read. Both stay at version 1. | A consumer that compares exact dicts or parses fixed text columns must accept the new keys and column. |
| The `recorded` copy counter counts the bytes the Recording stores: 32 per digest Message, 0 for `off`. | Nobody for `full` Channels, which count the same bytes as before. |

## Run-impacting changes

- Manifest bytes: none for a Manifest without `record`. The builder writes the
  key only for `digest` and `off` Channels.
- Manifest hashes: no algorithm change; still SHA-256 of the exact file bytes.
- Run behavior: a `digest` Channel stores the SHA-256 of each payload and an
  `off` Channel stores nothing. The Run still computes the SHA-256 of each
  digest payload, about 1.1 ms per 2.76 MB camera frame on the measured
  machine ([bench](../bench/record-mode-digest.md)).
- Exit-code classification: an invalid `record` value and a Replay of a
  `digest` or `off` source Channel are Manifest errors (exit `2`).
- Recording bytes: none for a Manifest without `record`; an explicit
  `record: "full"` gives the same Recording bytes. `digest` and `off` Channels
  use the layout above. Cross-release bit identity is not promised.
