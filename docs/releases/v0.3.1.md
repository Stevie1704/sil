# SiL 0.3.1

This patch fixes Process participant hangs during request writes, protects
Replay inputs from Run outputs, closes runner descriptors on exec, and
improves failure reports. It also rejects repeated Manifest keys consistently
and corrects command path resolution. The changes since
[0.3.0](v0.3.0.md) are in
[PR #395](https://github.com/Stevie1704/sil/pull/395) and
[PR #396](https://github.com/Stevie1704/sil/pull/396).

## Supported machine class and determinism

Unchanged from 0.3.0. Linux x86-64 with glibc 2.36 (Debian bookworm) or
newer. The native archive and the runtime image come from the same pinned
bookworm toolchain. The same compiled artifacts, Manifest bytes and
dependency versions on the same machine class produce identical Recordings.
Bit identity with earlier releases or across machine classes is not promised.

## Compatibility changes and migration

| Change | Who must act |
| --- | --- |
| A later Process command argument is resolved against the Manifest directory only when it contains `/` and names an existing entry. A bare word stays literal. | A Manifest that names an input beside it as `file.py` or `data.csv` must use `./file.py` or `./data.csv`. A bare executable still uses `PATH`. See [command paths](../step-protocol.md#command-path-decision). |
| Relative command paths use the Manifest directory, rather than the runner's invocation directory. | A caller that relied on its working directory must make the paths relative to the Manifest or use absolute paths. |
| A repeated key in any Manifest object is a Manifest error (exit `2`); an earlier value is no longer silently discarded. | Remove repeated keys. `sil manifest validate` lists the repeated keys before checking other errors. See [validation](../running.md#validate-a-manifest). |
| A Recording, provenance or failure-report output that is the same file as a Replay input is refused (exit `2`), including symlinks and hard links. | Choose separate output paths. The refusal preserves the Replay input and writes no Recording, provenance record or failure report. See [the Run contract](../running.md#run-contract). |

The Python tools that read a Manifest now share the kernel's JSON parse rules:
bundle sealing, footprint calculation, heap and source-scope capture, and the
example generators reject repeated keys, non-finite numbers and lone surrogate
escapes. They no longer return a result for these inputs or silently discard
a repeated key before generating a Manifest. Existing valid inputs need no
change beyond the command path rules above.

## Process deadlines and descriptors

`--participant-timeout-ms` now bounds the complete exchange: writing `init`
or `step` and waiting for `ready` or `step_done`. A child that stops reading
stdin cannot leave the runner stuck in a write beyond its deadline. A missed
deadline is a Run failure (exit `1`, category `timeout`). Partial writes and
reads do not restart the deadline. Without the option, waits remain unlimited,
but SIGINT, SIGTERM and SIGHUP also end a Run blocked on a request write.
See [the Step protocol](../step-protocol.md).

Runner-owned descriptors close on exec. A Process participant no longer
inherits the Recording, another participant's pipes, Arena or clock-region
descriptors, or diagnostics output descriptors. Its protocol descriptors are
stdin, stdout and stderr; it opens shared-memory regions by path as before.

## Failure reports

Failure reports keep schema version 1, with more precise facts:

- A wrong-size publication or full subscriber route from a Process participant
  includes the publishing Participant, Step index and Virtual time, with
  category `run`.
- A malformed `ready` response, such as a non-object or a non-string `op`,
  `reason` or `failure`, has category `protocol` and names the Participant.
  Its exit code remains `1`.

Known limits remain: a deadline missed during a write still says it was
waiting for the response; Native publication failures and Replay publication
failures do not gain the Process participant's Step facts. The diagnostics
report can name a failure-report path even when the Replay input protection
refused to write that file.

## Run-impacting changes

- Manifest bytes: no format change or automatic rewrite. Migrating a bare
  command-file argument to `./file` changes the authored Manifest bytes.
- Manifest hashes: no algorithm change; still SHA-256 of the exact file bytes.
  A command path migration changes the Manifest hash.
- Run behavior: command paths follow the corrected rules; repeated keys and
  outputs on Replay inputs are refused; request writes obey the Response
  deadline and termination signals; runner descriptors close on exec; failure
  reports gain the facts and classification described above.
- Exit-code classification: repeated keys and outputs on Replay inputs are
  Manifest errors (exit `2`); a stalled request write with a deadline is a Run
  failure (exit `1`). A malformed `ready` response remains exit `1`, with
  category `protocol` rather than `run`.
- Recording bytes: none by design for a Run whose commands resolve identically
  and that completes before all deadlines. Cross-release bit identity is not
  promised.
