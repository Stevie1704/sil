# SiL 0.2.0

## Breaking change: one `sil` command

The Python package installs one console command, `sil`. It replaces the
`sil-*` console entry points of 0.1.0, which this release removes without
aliases. `sil --help` lists every subcommand, and `sil <group> --help` lists
the subcommands of a group.

| 0.1.0 | 0.2.0 |
| --- | --- |
| `sil-check` | `sil check` |
| `sil-compare` | `sil compare` |
| `sil-footprint` | `sil footprint` |
| `sil-run` (native) | `sil run`, or `sil-run` as before |
| `sil-bundle seal`, `verify`, `run` | `sil bundle seal`, `verify`, `run` |
| `sil-matrix` | `sil bundle matrix` |
| `sil-csv` | `sil recording csv` |
| `sil-window` | `sil recording window` |
| `sil-fmi-inspect` | `sil fmi inspect` |
| `sil-fmu-couple` | `sil fmi couple` |
| `sil-fmu-replay` | `sil fmi replay` |
| `sil-fmu-substitute` | `sil fmi substitute` |
| `sil-schema-import` | `sil schema import` (needs the `sil[dwarf]` extra) |
| `sil-acc` | removed; use `python -m sil.examples.acc.manifest` |
| `sil-participant` | removed; Manifests start `python3 -m sil.participant` |

Each subcommand keeps the arguments, exit codes and report formats of the
command it replaces. `sil run` replaces its process with the native `sil-run`
found on `PATH`, so the Run's exit code is the runner's; when `sil-run` is not
on `PATH`, `sil run` exits `127`. The native `sil-run` and `silschema`
commands and the container `ENTRYPOINT` do not change.

Help, usage and error messages name the new subcommands. Diagnostic text is
not a compatibility promise.

## The docs ship with the installation

The wheel and the runtime image contain the user docs, the glossary, the
support statement and an agent guide, as they are in this release. They need
no source checkout and no network access:

| Command | Effect |
| --- | --- |
| `sil docs` | list the topics, each with a one-line summary |
| `sil docs <topic>` | print one doc as Markdown, for example `sil docs step-protocol` |
| `sil docs --path` | print the directory of the docs, to search them |

`sil docs agent-guide` is the entry point for a coding agent that onboards a
system under test. A link to a file that does not ship points to the file at
this release's tag in the repository.

`sil docs recording-queries` includes the bounded query contract.
`sil examples` lists the installed adapter, binding, recorded-input and bundle
preparation sources; `sil examples --path` locates them, and
`sil examples --dir examples` copies them into a new or empty directory.
The user guides run from that exported layout without cloning SiL. Links to
packaged example files resolve offline. `sil docs examples` states the
compiler, native headers and external FMU artifacts each workflow needs.

## Read a Recording without a script

`sil recording channels` lists the Channels of a Recording with their Schema,
Message count, earliest and latest virtual time and the Manifest hash.
`sil recording show` prints the Messages decoded with the Schemas stored in
the Recording, filtered by Channel and virtual time. Both have a `--json`
form: the `sil_recording_channels` report and one `sil_recording_show` object
per Message. `sil docs running` describes them.

## Measure Runs, repeat them, and render reports

Run diagnostics measure the host execution cost of a Run. They are opt-in:
without a diagnostics option, `sil run` is `sil-run` as before, with no
measurement.

| Command | Effect |
| --- | --- |
| `sil run manifest.json --diagnostics -o run.mcap` | the Run, plus a `sil_run_diagnostics` v1 report, `run.mcap.diagnostics.json`, and a summary on stdout |
| `sil run manifest.json --no-recording --diagnostics-out results/run.json --html results/run.html` | the same without a Recording, with an explicit report path and a standalone HTML report |
| `sil benchmark manifest.json --repeats 10 --warmup 1 --out results --html results/report.html` | serial fresh Runs, each with its own directory of evidence, and `results/summary.json`, a `sil_benchmark_report` v1 |
| `sil diagnostics render results/summary.json --html copy.html` | the HTML report of a saved report, with nothing executed again |

- The measurements come from `sil-run-diagnostics`, a second installed
  runner built from the same kernel sources with a collector. It starts
  through `sil-diagnostics-launcher`, so the runner's peak memory is not the
  peak of the Python process that started it. The native archive and the
  runtime image contain both commands; the wheel contains the HTML assets.
- A report gives lifecycle phases, inclusive timing per Native Task, Process
  Step and Replay publication Slot, bounded statistics, and CPU time and
  largest-process peak resident memory per scope. `sil docs running` says what
  each value includes and what v1 does not measure (no `--steps`, no total
  memory, no TOPS); `sil docs diagnostics-report` is the report contract.
- The diagnostics runner writes the same Recording bytes and exit codes as
  `sil-run`. Its timings include the collector's own cost: a Run that just
  meets a response deadline can miss it with diagnostics on.
- The HTML report is one file that opens offline, with its content readable
  without JavaScript.
- This replaces part of the #63 decision
  ([ADR 0004](https://github.com/Stevie1704/sil/blob/main/docs/adr/0004-opt-in-run-diagnostics-runner.md)).
  It does not change the #229 reference baseline or resolve #125.

## Compatibility

| Surface | Status in this release |
| --- | --- |
| Native participant C ABI | `SIL_ABI_VERSION 1`; unchanged |
| Manifest document | unchanged; `-m sil.participant` and `-m sil.fmi` keep their module paths |
| Step protocol | unchanged |
| Recording contract | unchanged |
| Runner command line | `sil-run` unchanged; new `sil-run-diagnostics` (the `sil-run` options plus `--diagnostics-out`) and `sil-diagnostics-launcher` |
| Native schema-generation tool | unchanged |
| Python API | modules unchanged; the `sil-*` console entry points are replaced by `sil`; new `sil docs`, `sil recording channels`, `sil recording show`, `sil benchmark` and `sil diagnostics render`, and the diagnostics options of `sil run`; `sil.recording.read_records` takes optional Channel and time filters |
| Container entry point | unchanged |

## Run-impacting changes

- Manifest bytes: none.
- Manifest hashes: none.
- Run behavior: none.
- Exit-code classification: none.
- Recording bytes: none. A Recording, receipt or generated header keeps the
  tool name 0.1.0 wrote into it: the MCAP `library` field and receipt names
  `sil-csv` and `sil-window`, the receipt authors `sil-fmu-replay`,
  `sil-fmu-couple` and `sil-fmu-substitute`, the JUnit suite name
  `sil-matrix`, and the header comment of `sil schema import`.
