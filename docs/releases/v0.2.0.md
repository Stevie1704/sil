# SiL 0.2.0

This release replaces the `sil-*` commands with one `sil` command, ships the
docs and an agent skill with the installation, and adds FMI 2.0 and more FMI
3.0 types, Recording tools, regression bundles, Run evidence and opt-in Run
diagnostics. It also bounds the Step protocol and the Process participant
lifetime, which changes Run behavior at the limits below.

## Supported machine class and determinism

Unchanged from 0.1.0. This release is supported on Linux x86-64 with glibc at
Debian bookworm level or newer. The reference runtime is the pinned
`python:3.13.7-slim-bookworm` image used to build the release image. The same
compiled artifacts, the same Manifest bytes, and the same dependency versions
on the same OS, CPU architecture, and libc produce a bit-identical Recording.
Bit identity across machine classes is not promised, and a developer build is
not the release artifact.

## Breaking change: one `sil` command

The Python package installs one console command, `sil`. It replaces the
`sil-*` console entry points of 0.1.0, which this release removes without
aliases. `sil --help` lists every subcommand, and `sil <group> --help` lists
the subcommands of a group.

| 0.1.0 | 0.2.0 |
| --- | --- |
| `sil-check` | `sil check` |
| `sil-footprint` | `sil footprint` |
| `sil-acc` | removed; use `python -m sil.examples.acc.manifest` |
| `sil-participant` | removed; Manifests start `python3 -m sil.participant` |
| `sil-run` (native) | `sil run`, or `sil-run` as before |

The other commands of this release are new in it and have only their `sil`
form: `sil compare`, `sil bundle`, `sil recording`, `sil fmi`, `sil manifest`,
`sil new`, `sil schema`, `sil docs`, `sil examples`, `sil skill`,
`sil benchmark` and `sil diagnostics`. Development builds between the two
releases had `sil-*` names for some of them; those names are gone.

`sil check` and `sil footprint` accept every argument of the command they
replace and keep its exit codes. `sil check` adds `--participant-timeout-ms`,
`--keep DIR` (keep both Recordings) and `--json` (the `sil_check_report`,
with the first difference). `sil run` replaces its process with the native
`sil-run` found on `PATH`, so the Run's exit code is the runner's; when
`sil-run` is not on `PATH`, `sil run` exits `127`. The native `sil-run` and
`silschema` commands and the container `ENTRYPOINT` keep their names.

Help, usage and error messages name the new subcommands. Diagnostic text is
not a compatibility promise.

## The docs ship with the installation

The wheel and the runtime image contain the user docs, the glossary, the
support statement and an agent guide, as they are in this release. They need
no source checkout and no network access:

| Command | Effect |
| --- | --- |
| `sil docs` | list the topics, each with a one-line summary |
| `sil docs <topic>` | print one doc as Markdown, for example `sil docs step-protocol` |
| `sil docs --path` | print the directory of the docs, to search them |

`sil docs agent-guide` is the entry point for a coding agent that onboards a
system under test. A link to a file that does not ship points to the file at
this release's tag in the repository.

`sil docs recording-queries` includes the bounded query contract.
`sil examples` lists the installed adapter, binding, recorded-input and bundle
preparation sources; `sil examples --path` locates them, and
`sil examples --dir examples` copies them into a new or empty directory.
The user guides run from that exported layout without cloning SiL. Links to
packaged example files resolve offline. `sil docs examples` states the
compiler, native headers and external FMU artifacts each workflow needs.

For a coding agent, `sil skill install` writes the agent skill of this
version into `.agents/skills/sil/` and links `.claude/skills/sil` to it
(`--user` for the home directory, `--dir DIR` for another directory).
`sil manifest validate` lists every error of a Manifest without a Run, and
`sil new participant` writes a minimal Participant with a Manifest builder.

## Run evidence

| Artifact | Content |
| --- | --- |
| `<recording>.provenance.json` | written by every Run: the Manifest hash, the runner, the digests of the participant executables and command files, the machine class and the exit code. `--provenance PATH` gives another path |
| `<recording>.failure.json` | written by a Run that ends with exit `1` or `2`: the category, the failed Participant, its exit status or signal, the Step and Virtual time, and the last 20 lines of its stderr |

`sil docs running` describes both. A successful Run removes a failure report
that an earlier failed Run left at the same path.

## Read a Recording without a script

`sil recording channels` lists the Channels of a Recording with their Schema,
Message count, earliest and latest virtual time and the Manifest hash.
`sil recording show` prints the Messages decoded with the Schemas stored in
the Recording, filtered by Channel and virtual time. Both have a `--json`
form: the `sil_recording_channels` report and one `sil_recording_show` object
per Message. `sil docs running` describes them.

`sil recording query` returns bounded fields, summaries and predicate
matches (for example a threshold crossing) as a versioned
`sil_recording_query` report (`sil docs recording-queries`).

## Recorded input, comparison and regression bundles

| Command | Effect |
| --- | --- |
| `sil recording csv` | convert timestamped CSV signals into a Recording for Replay, with a receipt (`sil docs recorded-input`) |
| `sil recording window` | select a window of a Recording, with a warm-up, and rebase it to time 0 (`sil docs replay`) |
| `sil compare` | compare a Recording with a reference under an explicit comparison contract, with a `sil_comparison_report` (`sil docs comparison`) |
| `sil bundle seal`, `verify`, `run` | seal an adopter regression with the identity of each file and the runtime, verify it, and run it offline into its own evidence directory |
| `sil bundle matrix` | run a list of sealed bundles as one CI job, with isolated evidence and a JUnit summary (`sil docs regression-bundles`) |

Replay now streams a Recording instead of loading it, so the memory of a
Replay participant does not grow with the length of the Recording.

## FMUs and shared libraries

- `python -m sil.fmi` also drives FMI 2.0 co-simulation FMUs, under the
  profile in `sil docs fmi` (scalar `Real`, `Integer` and `Boolean`; OSMP
  binary variables at the Importer edge). It is not general FMI 2.0
  conformance.
- The FMI 3.0 Importer maps `Float32`, `Int32`, `UInt32` and `UInt64` scalars,
  fixed-size numeric arrays, bounded `Binary` payloads, and clocked
  FMI-LS-BUS CAN nodes.
- `sil fmi inspect` reports whether this Importer can drive an FMU.
  `sil fmi couple` authors a Run of FMUs coupled through Channels, with a
  validated execution order and explicit initial values. `sil fmi replay`
  replays a Recording into one FMU, and `sil fmi substitute` replaces one
  coupled FMU with its Recording (`sil docs fmu-coupling`).
- The shared-library adapter binds several Channels and entry points of one
  library (`sil docs library`). `sil schema import` writes a flat Schema from
  the DWARF layout of a C type; it needs the `sil[dwarf]` extra. `silschema`
  rejects a Schema name that it cannot turn into a valid C name.
- The standalone Classical CAN bus FMU in `models/can/` is a separate model
  product with its own [release statement](https://github.com/Stevie1704/sil/blob/v0.2.0/models/can/RELEASE.md).
  It is not part of the SiL release artifacts.

## Process participants

- The Step protocol is bounded at the run boundary:
  `--max-protocol-line-bytes` (default 16 MiB),
  `--max-step-output-messages` (default 1024) and
  `--max-step-inline-payload-bytes` (default 64 MiB). A Participant that
  exceeds one fails the Run (exit `1`, failure category `guard`).
- A Process participant is the leader of its own process group. At shutdown,
  SIGTERM and then SIGKILL go to the group, and the runner waits for the group
  during the grace periods. This is a lifetime boundary, not a sandbox.
- SIGINT, SIGHUP and SIGTERM to the runner interrupt the Run: the runner
  stops at the next safe point, shuts down the Participants, closes the
  Recording, and exits `1`.
- The clock shim has a `threads` policy (`allow`, `report`, `reject`) for
  thread creation by a shimmed Process participant (`sil docs running`).

## Measure Runs, repeat them, and render reports

Run diagnostics measure the host execution cost of a Run. They are opt-in:
without a diagnostics option, `sil run` is `sil-run` as before, with no
measurement.

| Command | Effect |
| --- | --- |
| `sil run manifest.json --diagnostics -o run.mcap` | the Run, plus a `sil_run_diagnostics` v1 report, `run.mcap.diagnostics.json`, and a summary on stdout |
| `sil run manifest.json --no-recording --diagnostics-out results/run.json --html results/run.html` | the same without a Recording, with an explicit report path and a standalone HTML report |
| `sil benchmark manifest.json --repeats 10 --warmup 1 --out results --html results/report.html` | serial fresh Runs, each with its own directory of evidence, and `results/summary.json`, a `sil_benchmark_report` v1 |
| `sil diagnostics render results/summary.json --html copy.html` | the HTML report of a saved report, with nothing executed again |

- The measurements come from `sil-run-diagnostics`, a second installed
  runner built from the same kernel sources with a collector. It starts
  through `sil-diagnostics-launcher`, so the runner's peak memory is not the
  peak of the Python process that started it. The native archive and the
  runtime image contain both commands; the wheel contains the HTML assets.
- A report gives lifecycle phases, inclusive timing per Native Task, Process
  Step and Replay publication Slot, bounded statistics, and CPU time and
  largest-process peak resident memory per scope. `sil docs running` says what
  each value includes and what v1 does not measure (no `--steps`, no total
  memory, no TOPS); `sil docs diagnostics-report` is the report contract.
- The diagnostics runner writes the same Recording bytes and exit codes as
  `sil-run`. Its timings include the collector's own cost: a Run that just
  meets a response deadline can miss it with diagnostics on.
- The HTML report is one file that opens offline, with its content readable
  without JavaScript.
- This replaces part of the #63 decision
  ([ADR 0004](https://github.com/Stevie1704/sil/blob/v0.2.0/docs/adr/0004-opt-in-run-diagnostics-runner.md)).
  It does not change the #229 reference baseline or resolve #125.

## Compatibility

| Surface | Status in this release |
| --- | --- |
| Native participant C ABI | `SIL_ABI_VERSION 1`; `include/sil/participant.h` unchanged |
| Clock region (`include/sil/clock_region.h`) | one appended field, `thread_policy`; the shim and the runner of one release are used together |
| Manifest document | version `1`; one new optional field, `shim.threads`. A 0.1.0 Manifest is valid and has the same hash |
| Step protocol | protocols `1` and `2` as before; new size guards at the run boundary, with defaults |
| Recording contract | unchanged |
| Runner command line | `sil-run` adds `--max-protocol-line-bytes`, `--max-step-output-messages`, `--max-step-inline-payload-bytes` and `--provenance`; new `sil-run-diagnostics` (the `sil-run` options plus `--diagnostics-out`) and `sil-diagnostics-launcher` |
| Native schema-generation tool | `silschema` rejects Schema names that are not valid C names |
| Python API | the `sil-*` console entry points are replaced by `sil`; new modules and commands as above; `sil.recording.read_records` takes optional Channel and time filters; `run_simulation` takes the Participant response deadline |
| Container entry point | unchanged |

## Run-impacting changes

- Manifest bytes: none.
- Manifest hashes: none.
- Run behavior:
  - A Process participant above a Step-protocol size guard now fails the Run.
    The defaults are above the payloads of the examples and benchmarks.
  - A Process participant runs in its own process group, and its
    descendants get the shutdown signals.
  - SIGINT, SIGHUP and SIGTERM end the Run as a Run failure after cleanup.
  - Every Run writes a provenance side-car, and a failed Run writes a
    failure report, next to the Recording.
- Exit-code classification:
  - A size-guard violation and an interrupted Run are exit `1`.
  - A Replay Recording without its MCAP footer (cut short) is now a
    Manifest error, exit `2`.
- Recording bytes: none. Recordings, receipts and generated headers keep
  the tool names of the development builds: the MCAP `library` field and receipt names
  `sil-csv` and `sil-window`, the receipt authors `sil-fmu-replay`,
  `sil-fmu-couple` and `sil-fmu-substitute`, the JUnit suite name
  `sil-matrix`, and the header comment of `sil schema import`.
