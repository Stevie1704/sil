# SiL 0.2.0

## Breaking change: one `sil` command

The Python package installs one console command, `sil`. It replaces the
`sil-*` console entry points of 0.1.0, which this release removes without
aliases. `sil --help` lists every subcommand, and `sil <group> --help` lists
the subcommands of a group.

| 0.1.0 | 0.2.0 |
| --- | --- |
| `sil-check` | `sil check` |
| `sil-compare` | `sil compare` |
| `sil-footprint` | `sil footprint` |
| `sil-run` (native) | `sil run`, or `sil-run` as before |
| `sil-bundle seal`, `verify`, `run` | `sil bundle seal`, `verify`, `run` |
| `sil-matrix` | `sil bundle matrix` |
| `sil-csv` | `sil recording csv` |
| `sil-window` | `sil recording window` |
| `sil-fmi-inspect` | `sil fmi inspect` |
| `sil-fmu-couple` | `sil fmi couple` |
| `sil-fmu-replay` | `sil fmi replay` |
| `sil-fmu-substitute` | `sil fmi substitute` |
| `sil-schema-import` | `sil schema import` (needs the `sil[dwarf]` extra) |
| `sil-acc` | removed; use `python -m sil.examples.acc.manifest` |
| `sil-participant` | removed; Manifests start `python3 -m sil.participant` |

Each subcommand keeps the arguments, exit codes and report formats of the
command it replaces. `sil run` replaces its process with the native `sil-run`
found on `PATH`, so the Run's exit code is the runner's; when `sil-run` is not
on `PATH`, `sil run` exits `127`. The native `sil-run` and `silschema`
commands and the container `ENTRYPOINT` do not change.

Help, usage and error messages name the new subcommands. Diagnostic text is
not a compatibility promise.

## Compatibility

| Surface | Status in this release |
| --- | --- |
| Native participant C ABI | `SIL_ABI_VERSION 1`; unchanged |
| Manifest document | unchanged; `-m sil.participant` and `-m sil.fmi` keep their module paths |
| Step protocol | unchanged |
| Recording contract | unchanged |
| Runner command line | unchanged |
| Native schema-generation tool | unchanged |
| Python API | modules unchanged; the `sil-*` console entry points are replaced by `sil` |
| Container entry point | unchanged |

## Run-impacting changes

- Manifest bytes: none.
- Manifest hashes: none.
- Run behavior: none.
- Exit-code classification: none.
- Recording bytes: none. A Recording, receipt or generated header keeps the
  tool name 0.1.0 wrote into it: the MCAP `library` field and receipt names
  `sil-csv` and `sil-window`, the receipt authors `sil-fmu-replay`,
  `sil-fmu-couple` and `sil-fmu-substitute`, the JUnit suite name
  `sil-matrix`, and the header comment of `sil schema import`.
