# SiL 0.3.0

This release adds source-aware CPU and heap profiling, opt-in Native source
scopes, Recording export and Foxglove playback, and configurable provenance
ownership with less hash work. It also changes the provenance side-car to
schema version 2 and makes a failed Recording write a Run failure.

## Supported machine class and determinism

Unchanged from 0.2.1. Linux x86-64 with glibc 2.36 (Debian bookworm) or
newer. The native archive and the runtime image come from the same pinned
bookworm toolchain. The same compiled artifacts, Manifest bytes and
dependency versions on the same machine class produce identical Recordings.
Bit identity with earlier releases or across machine classes is not promised.

## Breaking changes

| Change | Who must act |
| --- | --- |
| The provenance side-car is schema version 2. Each digest has `digest_state`, the record has `provenance_mode`, and `recording` is always an object. | A reader of schema version 1. See [the migration](../running.md#migrate-from-schema-version-1). |
| A failed Recording write or close is a Run failure, exit `1`. The Run stops after the first failed write. | A caller that saw exit `0` for such a Run ([details](../running.md#recording-digest)). |
| A build from source needs OpenSSL 3.0 or newer with its static library. | A source build only. A built runner has no OpenSSL runtime dependency ([decision](../adr/0006-sha256-backend-static-openssl.md)). |

## Profiling

`sil profile` captures one fresh Run and writes a profile directory with a
`sil_profile_report` (version 1). See [the profile report](../profile-report.md).

| Command | Effect |
| --- | --- |
| `sil profile MANIFEST --out DIR --collector cpu` | CPU samples with Linux perf, correlated with Activations and source lines |
| `sil profile MANIFEST --out DIR --collector heap` | allocations with Heaptrack, for the runner and unshimmed Process participants |
| `sil profile render DIR/profile.json` | an offline HTML report: flame graph, Activation timeline, Task drill-downs, callers, source-line hotspots and retained Activation outliers |
| `sil profile diff BASE/profile.json NEW/profile.json` | compare two saved sets, with optional paired benchmark inputs |

perf and Heaptrack are optional host tools that SiL does not ship. The
qualified versions are in [SUPPORT.md](../../SUPPORT.md). Ordinary `sil run`,
`sil-run` and the runtime image need neither tool nor any privilege.

## Source scopes

A source owner can mark selected C calls in a Native library with
`SIL_SOURCE_SCOPE(id, name)` from `include/sil/source_scope.h`. One capture
gives the exact count, entry order, nesting and inclusive host time of these
calls in each Native Task Activation ([guide](../running.md#source-scopes),
[decision](../adr/0007-source-owned-native-scope-observer.md)).

The native development archive includes `sil/source_scope.h`, the observer
`libsil_source_scope.so.1` and the `libsil_source_scope.so` link name. The
runtime image includes the observer for instrumented Native participants.
Release smoke checks compile a consumer against the installed archive,
capture its calls in native and container Runs, compare their Recordings
with ordinary Runs, and render copied scope evidence offline.

## Visualization

| Command | Effect |
| --- | --- |
| `sil recording export RUN.mcap --profile visualization-json -o OUT.mcap` | an indexed MCAP that external file players such as Foxglove open directly, with a receipt |
| `sil playback serve` | serve a Recording to the playback controls of Foxglove; needs the `sil[foxglove]` extra (`foxglove-sdk==0.30.3`) |

`sil.visualization` gives the same export, indexed navigation, exact
snapshots and headless playback state from Python. The export is a
visualization derivative, not a Replay input. The Foxglove adapter is
qualified against Foxglove Desktop 3.5.0: pause with speed `0.0` keeps the
rate, and each Message's log time goes out as server time before the Message.
See [visualization](../visualization.md).

## Provenance mode

`--provenance-mode full|external` selects who owns artifact identity. The
default is `full`, which keeps the existing hashing. In `external` mode, the
runner omits the digests of its inputs and of the Recording. It keeps the
Manifest hash, path and file checks, topology checks and Replay verification.
Recording bytes do not change. `sil-run`, `sil run`, `sil benchmark` and
`sil profile` accept the option. See
[provenance mode](../running.md#provenance-mode).

The platform that uses `external` must bind the actual runner and inputs to its
execution record and hash the finalized Recording. The Manifest hash does not
identify the contents of the files that a Manifest names.

The Manifest hash is the SHA-256 of the exact file bytes. Replay verification
stays on in both modes. `sil check`, `sil bundle`, comparisons and the artifact
digests of a profile directory keep their hashes. `sil profile` in `external`
mode still hashes a Recording in its directory, as profile evidence.
[The managed-platform example](../running.md#managed-platform-example) shows the
duties of the platform.

## Less hash work in `full` mode

| Change | Effect | Dependency or limit |
| --- | --- | --- |
| SHA-256 uses OpenSSL EVP | Digests stay the same. Hardware acceleration is used where the CPU has it. | A build from source needs OpenSSL 3.0 or newer with its static library. |
| One digest for each canonical input path in one preparation | Participants that share an input cause one hash. | The reuse is for one preparation only. A later Run sees replaced bytes. |
| The Recording digest is calculated while the Run writes | A normal Run does not read the Recording again. | The same CPU work occurs during the Run, so the reported Run wall time now includes it. `full` mode has no measured end-to-end gain from this change. A failed write can cause one read of the file. |
| A profile command builds its artifact list once | Each finalized artifact has one hash. | The profile tool does not reuse the digest of the runner ([why](../profile-report.md#no-recording-digest-handoff)). |

[The qualification](../bench/provenance-qualification.md) gives the measured
results and limitations. The attribution for each change is from one arm64 macOS
machine. The x86-64 results are from one shared CI runner. The results do not
promise a speedup on your workload.

## Diagnostics and FMI

- `sil-run-diagnostics --hold-deadline PARTICIPANT` removes the Response
  deadline of one Process participant, so a debugger stop in it does not
  fail the Run. Every other Process participant keeps
  `--participant-timeout-ms`. `sil-run` rejects the option (exit `2`). See
  [running](../running.md).
- `sil-diagnostics-launcher` takes `--status-fd N` and `--environment-fd M`.
- The FMI Importer writes a stderr warning at start-up when a Run binds an
  OSMP configuration request (`InConfigRequest`): it does not do the
  `SensorViewConfiguration` exchange, so the bound input stays empty
  (#251). `sil fmi inspect` reports the same warning in its mapping
  `warnings`.

## Compatibility

| Surface | Status in this release |
| --- | --- |
| Native participant C ABI | unchanged, `SIL_ABI_VERSION 1`; new optional header `include/sil/source_scope.h` |
| Clock region | unchanged; use the runner and shim of one release together |
| Manifest document | unchanged, version `1` |
| Step protocol | unchanged, protocols `1` and `2` |
| Recording contract | unchanged |
| Provenance side-car | **changed**, schema version 2 (see above) |
| `sil_run_diagnostics` | version 1; new `configuration.provenance_mode` and `configuration.held_deadline_participant`. A report without them stays valid |
| `sil_benchmark_report` | version 1; new `policy.provenance_mode`. A report without it stays valid and reads as `full` |
| `sil_profile_report` | new, version 1 |
| `sil_fmi_inspection` | version 3; adds the mapping's `warnings` |
| Runner command line | `sil-run` adds `--provenance-mode`; `sil-run-diagnostics` adds `--hold-deadline`; existing use is unchanged |
| Runner exit codes | **changed**: a failed Recording write or close is exit `1` ([SUPPORT.md](../../SUPPORT.md)) |
| Native schema-generation tool | unchanged |
| Python API | additive: `sil profile`, `sil recording export`, `sil playback serve`, `sil.visualization`, indexed reads in `sil.recording`; new optional extra `sil[foxglove]` |
| Container entry point | unchanged; the image adds `libsil_source_scope.so.1` |

## Run-impacting changes

- Manifest bytes: none.
- Manifest hashes: none.
- Run behavior:
  - The Run stops after the first failed Recording write.
  - In `full` mode, the Recording digest is calculated during the Run, so
    the reported Run wall time includes it.
  - A Run that binds an OSMP configuration request writes a start-up
    warning to stderr.
- Exit-code classification: a failed Recording write or close is exit `1`.
- Recording bytes: none by design; cross-release bit identity is not promised.
